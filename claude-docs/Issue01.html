Issue 01 · branch mark-01

MATRIX//OS: console cibernético sobre a chuva digital

Proposta para migrar o matrix-rain para o ratatui, adicionar um console no estilo terminal antigo (menu lateral, área de trabalho e rodapé de status) e gerar um executável que roda numa janela própria, fora do terminal. A chuva continua sendo o “descanso de tela” sempre que não houver atividade.

ratatui 0.30crossterm 0.28sysinfo 0.39Rust 1.99 · edition 202102/11/2026

01Resumo

  • Um núcleo e duas “carcaças”. A simulação (chuva, temas, mensagens) e a interface viram código independente do backend. O mesmo binário roda no terminal (crossterm) ou numa janela nativa com GPU (feature desktop).
  • Dois modos. No Idle, só a chuva aparece, como hoje. No Console, a interface aparece sobre a chuva, que continua animando atenuada ao fundo. Depois de 60 s sem atividade (configurável), o console se recolhe sozinho.
  • Menus como dados. Cada menu é uma estrutura separada que implementa a trait Page. As páginas de configuração são só listas de itens tipados (toggle, slider, escolha, botão), como nos menus de opções de jogos. Para adicionar um comando basta um arquivo e uma linha de registro.
  • Uma única fonte de ações. Menu, atalho de teclado e linha de comando (> theme dracula) geram o mesmo Action. Não existem dois caminhos para fazer a mesma coisa.

02Executável fora do terminal

O princípio atual se mantém: um binário pequeno e rápido, sem runtime pesado. O ratatui desenha num Buffer de células e não sabe onde esse buffer vai parar. Isso permite trocar só o backend sem reescrever nenhum widget.

Opção A · lançador

Pacote .app/.exe que abre um terminal dedicado

Script empacotado que abre o WezTerm ou o Alacritty em tela cheia, com fonte e cores próprias, rodando o binário.

+ Nenhum código novo. − Depende de um terminal instalado. Não é um executável de verdade.

Opção B · janela nativa

Backend ratatui em GPU (winit + wgpu)

Uma feature desktop troca o CrosstermBackend por um backend que renderiza as células numa janela. Os candidatos são ratatui-wgpu ou egui_ratatui, a decidir num spike na Fase 5. Os widgets são exatamente os mesmos.

+ Binário único, fonte embutida, efeitos de CRT (scanlines, brilho) via shader. − Mais dependências e é preciso empacotar a fonte.

Opção C · navegador

WASM com Ratzilla

O mesmo núcleo compilado para wasm32, renderizando no DOM ou num canvas. Bom para demonstração e divulgação.

+ Roda em qualquer lugar e não precisa de instalação. − Sem acesso ao status real da máquina, então o rodapé fica limitado.

Recomendação: B, mantendo o terminal como alvo padrão. Os detalhes de distribuição ficam na Fase 6:

  • Empacotamento com cargo-bundle (.app no macOS, .msi no Windows, .deb no Linux).
  • #![windows_subsystem = "windows"], para não abrir uma janela de console no Windows.
  • Assinatura e notarização no macOS.
As versões e APIs exatas dos backends de GPU não foram verificadas localmente: só ratatui, wgpu, winit e egui estão no cache do cargo. O spike da Fase 5 confirma isso antes de qualquer compromisso. Atenção também à fonte: ela precisa de katakana half-width com largura de 1 célula, senão a grade da chuva desalinha.

04Arquitetura

O fluxo é unidirecional, no estilo Elm/TEA, que é o padrão recomendado pela documentação do ratatui. Eventos viram Action, só o update altera o estado e o view é uma função pura do estado.

Evento (tecla/mouse/resize/tick)
   │
   ▼
Mode::handle(evento) ──► Option<Action>      ◄── Command::run(args)  (linha de comando)
   │                                          ◄── Item::activate()    (menu)
   ▼
App::update(Action)  ── único lugar que muda o estado
   │
   ▼
App::view(frame)     ── RainWidget + Shell(Sidebar, Page, Prompt, Footer)

Contratos de extensão

/// Uma intenção. Menus, atalhos e comandos produzem isto — nunca mutam o App direto.
pub enum Action {
    SetTheme(usize), SetSpeed(f32), ToggleFullscreen, ShowMessage, RestartRain,
    Navigate(PageId), Back, OpenPrompt, RunCommand(String),
    Apply, Discard, ResetDefaults, Notify(Toast), RequestExit,
}

/// Um menu da barra lateral.
pub trait Page {
    fn id(&self) -> PageId;
    fn title(&self) -> &str;
    fn icon(&self) -> char { '▸' }
    fn render(&mut self, area: Rect, buf: &mut Buffer, ctx: &Ctx);
    fn on_key(&mut self, key: KeyEvent, ctx: &Ctx) -> Option<Action>;
    /// Dicas de tecla mostradas no rodapé quando esta página tem foco.
    fn hints(&self) -> &[(&str, &str)] { DEFAULT_HINTS }
}

/// Item de configuração no estilo menu de jogo.
pub enum Item {
    Toggle { label: &'static str, get: fn(&Settings) -> bool, set: fn(&mut Settings, bool) },
    Slider { label: &'static str, range: RangeInclusive<f32>, step: f32, get: …, set: … },
    Choice { label: &'static str, options: fn(&Ctx) -> Vec<String>, get: …, set: … },
    Button { label: &'static str, action: fn() -> Action, confirm: bool },
}

/// SettingsPage genérica: a maioria dos menus é só uma lista de Items.
pub struct SettingsPage { id: PageId, title: &'static str, items: Vec<Item>, cursor: usize }

/// Comando de texto da linha de comando.
pub trait Command {
    fn name(&self) -> &'static str;
    fn aliases(&self) -> &[&'static str] { &[] }
    fn help(&self) -> &'static str;
    fn complete(&self, _arg: &str, _ctx: &Ctx) -> Vec<String> { vec![] }
    fn run(&self, args: &[&str], ctx: &Ctx) -> Result<Action, String>;
}

Exemplo: adicionar um menu novo

// pages/audio.rs  — arquivo novo
pub fn page() -> SettingsPage {
    SettingsPage::new(PageId::Audio, "ÁUDIO", vec![
        Item::toggle("BIPES", |s| s.beeps, |s, v| s.beeps = v),
        Item::slider("VOLUME", 0.0..=1.0, 0.1, |s| s.volume, |s, v| s.volume = v),
    ])
}

// pages/mod.rs — uma linha
pub fn registry() -> Vec<Box<dyn Page>> {
    vec![ Box::new(video::page()), Box::new(rain::page()), /* … */ Box::new(audio::page()) ]
}

05Modos e ciclo de inatividade

ModoEntra quandoMostraTeclas
IdleInício · timeout sem input · Esc no nível raizSó a chuva, brilho total, mensagens escondidas ativasAtalhos atuais continuam (t, +, p…). Enter, F1 ou : abrem o console.
ConsoleEnter, F1 ou : no Idle, ou cliqueShell sobre a chuva atenuada (que continua animando)Navegação de menu, prompt, mouse
Lockq / Ctrl+C / item SAIRCaixa da trava (a atual)Texto + Enter, Esc cancela
  • Transições curtas. Abrir o console leva cerca de 250 ms: as linhas “digitam” de cima para baixo, com scanline. Fechar faz a mesma coisa ao contrário. Com reduzir movimento ligado, a transição é instantânea.
  • Timeout. O padrão é 60 s, configurável em SISTEMA e desativável. Ele não dispara com o prompt em edição nem com alterações não salvas, para não perder o que foi digitado.
  • Mensagens escondidas. Só aparecem no Idle, porque no Console a área central está ocupada.

06UX

Teclado primeiro, sem prender

Mapa de teclas consistente em todas as telas: ↑↓ move, ←→ ajusta, Enter confirma, Esc volta um nível. O mouse funciona também: clique, roda e arrastar slider.

Descobrível

O rodapé sempre mostra as teclas válidas naquela tela. F1 abre a ajuda contextual. O prompt autocompleta e sugere em caso de erro de digitação.

Pré-visualização ao vivo

Trocar o tema ou a velocidade muda a chuva do fundo na hora. Aplicar grava, Descartar volta ao estado anterior e Padrões pede confirmação.

Feedback claro

Toast curto para cada ação (“TEMA ▸ DRACULA”). Erro inline no prompt. Ponto de alterações não salvas no header.

Não depende só da cor

Seleção com marcador ▸ + inversão. Toggles com [■]/[ ] e texto. Contraste de texto ≥ 4.5:1 em todos os temas, com um tema de alto contraste.

Responsivo

Funciona a partir de 60×20. A sidebar encolhe para ícones e o rodapé esconde métricas em ordem de prioridade (o relógio e as dicas ficam por último). Abaixo do mínimo aparece um aviso centralizado.

Movimento com propósito

A animação indica mudança de estado, não enfeita. A opção de reduzir movimento desliga o embaralhamento de letras e as transições.

Persistente

As configurações sobrevivem a reinícios (config.toml). Se o arquivo estiver corrompido, o app usa os padrões e avisa, sem quebrar.

Visual moderno com cara de terminal antigo

  • Bordas arredondadas (BorderType::Rounded), títulos embutidos na borda e uma única cor de destaque derivada do accent do tema ativo. O console inteiro acompanha o tema.
  • Três níveis de texto (brilhante, normal, atenuado) tirados da paleta de 16 níveis que já existe. Nada de cor nova.
  • Detalhes cibernéticos discretos: sessão em hexadecimal, cursor em bloco piscando, sparklines e o efeito de decodificação já usado na trava, reaproveitado nos títulos ao abrir as páginas.
  • No desktop, há um shader opcional de CRT (curvatura leve, scanlines, bloom na cabeça das gotas), desligado com reduzir movimento.

SysMonitor roda numa thread própria: refresh a cada 1 s e envio de um SysSnapshot por mpsc. O loop de render só lê o último snapshot, então uma leitura lenta do sistema nunca derruba o FPS.

08Plano de entrega

Cada fase termina com make test e make lint verdes e com o app utilizável. Nenhuma fase deixa a branch quebrada.

  1. Separar o núcleo

    Quebrar o main.rs (1125 linhas) em core/ sem mudar comportamento. Os 2 testes atuais continuam passando.

    Aceite: diff só de movimentação de código, chuva idêntica.

  2. Chuva em ratatui

    RainWidget escreve no Buffer. O loop passa a usar Terminal::draw e a trava e o HUD são portados para widgets.

    Aceite: ≥ 60 FPS num terminal 240×70 com release, medido antes e depois. Se piorar mais de 15%, o rastro passa a ser desenhado só nas células que mudaram.

  3. Shell e modos

    Mode, Action, layout (header, sidebar, workspace, rodapé com dicas), transição de abertura e fechamento e timeout de inatividade.

    Aceite: testes com TestBackend do layout em 60×20, 80×24 e 160×48. Teste do ciclo Idle → Console → timeout → Idle.

  4. Menus e configuração

    Trait Page, SettingsPage, as páginas VÍDEO, CHUVA, MENSAGENS e ACESSIB., o fluxo Aplicar/Descartar/Padrões e a persistência em TOML (serde + toml + directories).

    Aceite: alterar → reiniciar → valor mantido. Config inválida → padrões + toast.

  5. Prompt e status

    Trait Command, os comandos builtin, histórico, autocompletar e sugestão. SysMonitor e as páginas SISTEMA e LOG.

    Aceite: todos os itens de menu têm um comando equivalente, verificado por teste. O rodapé não altera o tempo de frame.

  6. Janela desktop (spike + implementação)

    Comparar ratatui-wgpu e egui_ratatui, escolher um e criar a feature desktop com a fonte embutida, mais o shader de CRT opcional.

    Aceite: cargo run --features desktop abre a janela com o mesmo console. O katakana alinha na grade.

  7. Empacotamento

    make bundle com cargo-bundle, ícone e build de release no CI para macOS, Windows e Linux.

    Aceite: .app abre com duplo clique, sem terminal.

10Riscos e decisões em aberto

  • Desempenho do diff do ratatui com a tela inteira mudando. O renderer atual é muito otimizado (runs, um único write). Mitigação: medir na Fase 2 e manter o RainWidget simples. O ratatui já agrupa os escapes.
  • Fonte no desktop. Uma fonte monoespaçada com katakana half-width e licença livre que permita embutir. Precisa ser escolhida no spike.
  • Tecla para abrir o console. A proposta é Enter/F1/:. Os atalhos de uma letra atuais continuam funcionando no Idle, para não quebrar quem já usa.
  • Sair pelo console. O item SAIR abre a mesma trava com código. Fica em aberto se o código deve ser configurável (proposta: sim, em SISTEMA).
